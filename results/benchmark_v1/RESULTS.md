# Benchmark v1 results

Generated by `dfb report` from `results/benchmark_v1/*/*/metrics.json`. Test period 2026 Q2–Q3; data hard drives; counted per drive (see `EVALUATION.md`). Values are mean ± standard deviation over seeds.

**Thresholds are set on validation and applied unchanged to test** (decision E-2); the actual false-alarm rate that threshold gives on test is shown next to each detection rate. The test-curve column uses a threshold set on test itself, for comparison with results that set the threshold on test data.

Each run's `metrics.json` records the commit it ran on (`code_version`). Those were development commits, later combined into this repository's single commit. What changed between them was documentation, memory use when scoring, and new optional settings for the studies, not how the existing runs train, score or evaluate.

Why not accuracy: a model that always says "healthy" is right on 99.976% of test drive-days and catches no failures.
